8.1 Control Barrier Functions: The Core Idea

A Control Barrier Function (CBF) is a function h(x) that defines a safe set C = {x | h(x) ≥ 0}. If the control input satisfies a simple inequality, the system is guaranteed to stay in C forever.

Formal Definition

A function h: ℝⁿ → ℝ is a CBF for the system ẋ = f(x) + g(x)u if there exists an extended class-K function α such that:

$$\sup_{u \in U} [L_f h(x) + L_g h(x) \cdot u + \alpha(h(x))] \geq 0 \quad \forall x \in C$$

where L_f h and L_g h are Lie derivatives.

Intuition: The CBF condition says: "at every state, there exists a control input that either increases h (moves deeper into safety) or at least doesn't decrease h too fast." If this holds, the system can never leave the safe set.

8.2 The Quadratic Program (QP) Formulation

The CBF condition can be enforced via a Quadratic Program that minimally modifies a nominal control input u_nom:

$$\min_u \quad \|u - u_{\text{nom}}\|^2$$

subject to: $$L_f h(x) + L_g h(x) \cdot u + \alpha(h(x)) \geq 0$$

This finds the safest control closest to the nominal control. If the nominal control is already safe, the QP returns it unchanged. If not, it finds the minimal modification that restores safety.

8.3 VCP-CBF: Velocity-Constraint-Preserving

Standard CBFs assume simple dynamics. For car-like (bicycle model) dynamics, we need the Velocity-Constraint-Preserving CBF (VCP-CBF):

  • The bicycle model has nonholonomic constraints (cannot slide sideways)
  • The VCP-CBF preserves these constraints in the QP formulation
  • Ensures the filtered control is feasible for the actual robot

8.4 Safety Filtering vs End-to-End Safe RL

There are two paradigms for combining safety with RL:

ParadigmApproachProsCons
Post-hoc filterTrain RL normally, apply CBF to outputSimple, modular, preserves RL optimizationSafety is after-the-fact; may alter policy behavior
End-to-endEmbed safety constraint in loss/rewardPolicy inherently respects constraintsHard to optimize; constraint may dominate reward

Our Decision: Post-Hoc Filter (S32)

After extensive analysis (S16–S32), we chose the post-hoc filter approach:

  1. Train the RL policy without safety constraints
  2. At deployment, run the CBF QP to filter unsafe actions
  3. Log when filtering occurs for analysis
Key insight: The post-hoc filter lets the RL policy optimize purely for task performance. Safety is guaranteed at runtime by the QP. This separation of concerns is cleaner than trying to bake safety into the reward function.

8.5 3-Tier Infeasibility Handling (S23)

What if the QP has no feasible solution? We implemented a 3-tier fallback:

TierTriggerAction
1QP feasibleUse CBF-filtered control
2QP infeasible, backup availableUse backup controller (e.g., stop)
3All controls infeasibleEmergency stop + log anomaly
