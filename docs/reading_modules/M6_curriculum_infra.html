6.1 Curriculum Learning for Pursuit-Evasion

Curriculum learning trains on progressively harder tasks. In PE, this means gradually increasing the evader's capabilities so the pursuer faces stronger opponents over time.

Why Curriculum?

Without curriculum, a naive pursuer faces a fully-capable evader from episode 1 and never experiences success. The reward signal is entirely negative — no learning occurs. Curriculum ensures:

  1. Bootstrapping: Early episodes are easy enough for the pursuer to occasionally capture
  2. Progressive difficulty: The evader gets stronger as the pursuer improves
  3. Stable learning: Neither side is catastrophically overmatched at any point

Our Curriculum Design (G&I Reproduction)

ParameterStartEndDuration
Evader v_max0.0 m/s1.5 m/sFirst 30% of episodes (t_end_ratio = 0.3)
Evader FOV360° (omnidirectional)120° (2π/3)Same annealing window

The evader starts completely stationary (v_max = 0) with perfect sensing. The pursuer learns basic capture against a trivial opponent. Over the first 30% of training, the evader gains speed and loses omnidirectional vision.

Our Phase 1–3 Curriculum (Earlier Work)

Our original framework (S11–S84) used a more complex 4-level curriculum:

LevelDescriptionGate
L1Evader stationary or near-stationaryCR > 0.6
L2Evader slow, limited sensingCR > 0.5
L3Evader medium speed, partial obsCR > 0.45
L4Full capability—
Finding: The L3–L4 transition was where most runs collapsed. The gates were too permissive (CR > 0.45), allowing advancement before true competence. This led to 20+ sessions of debugging (S40–S52).

6.2 Checkpointing and Persistence

Checkpointing is essential for:

  • Resuming: Recover from crashes without losing progress
  • Evaluation: Test historical checkpoints against new opponents
  • Rollback: Restore best-performing policies when collapse is detected

Checkpoint Frequency

In the G&I reproduction, checkpoints are saved every 250 episodes. For a 5000-episode run, this produces 20 checkpoints.

Checkpoint Sweep Evaluation

A checkpoint sweep evaluates all saved checkpoints to understand the training trajectory:

  1. For each checkpoint, run 100 evaluation episodes
  2. Test against 3 opponent types: random, greedy, self-play
  3. Record capture rate for each
  4. Compute robustness = min(CR_random, CR_greedy, CR_selfplay)

This produces a trajectory like:

EpisodeCR_randomCR_greedyCR_selfplayRobustness
2500.100.020.010.01
10000.230.110.060.06
25000.650.990.350.35
50000.790.990.700.70
Insight: The checkpoint sweep reveals the true trajectory. A single final evaluation can be misleading — a policy might have peaked at episode 2500 and regressed by 5000. Only the sweep shows this.

6.3 Vectorized Environments

Vectorized environments run multiple independent environment instances in parallel, collecting experience batches.

Why Vectorize?

  • Speed: Parallel rollouts amortize overhead
  • Diversity: Different random seeds per env → more diverse experience
  • Batch size: Larger batches stabilize gradient estimates

Our Configuration

ParameterValue
Parallel envs2 (G&I reproduction, MADDPG)
Batch size1024
Replay buffer100,000 transitions

Earlier experiments (S94) implemented 8 parallel environments for faster training, but the G&I reproduction uses 2 for stability.

6.4 Automatic Mixed Precision (AMP)

AMP uses fp16 (16-bit floating point) for forward/backward passes and fp32 (32-bit) for critical operations. This speeds up training and reduces memory.

The NaN Problem

AMP initially caused NaN losses in our BiMDN experiments (S92–S93). Root causes:

  1. Scale mismatch: BiMDN outputs unbounded scale parameters that overflow in fp16
  2. Gradient underflow: Small gradients become zero in fp16
  3. Single critic: Q-value overestimation → explosion

The Fix

FixSessionEffect
Twin critics (Ackermann 2019)S93min(Q1, Q2) prevents overestimation
Gradient clippingS93Bounds gradient magnitude
Disable AMP for BiMDNS93Force fp32 for belief network
Wheelbase correction (0.15→0.30)S93Prevents unrealistic dynamics
Insight: NaN is not just a "numerical bug" — it indicates the algorithm is exploring a region of policy space where the value estimates are unreliable. The fix is both numerical (twin critics, clipping) and structural (correct dynamics).

6.5 Health Monitoring

We implemented automated health monitoring to detect collapse early:

Metrics Tracked

MetricPurposeAlert Threshold
Competitive Ratio (CR)Overall balanceCR > 0.8 or CR < 0.2 for 5+ checkpoints
Capture Rate vs RandomBasic competenceCR_random < 0.1 for 3+ checkpoints
Capture Rate vs GreedyAdvanced competenceCR_greedy < 0.1 for 3+ checkpoints
Loss magnitudeTraining stabilityLoss > 1000 or NaN
Gradient normExploding gradientsNorm > 100

Actions on Alert

  1. Log: Record the anomaly with full state
  2. Snapshot: Save current checkpoint for post-hoc analysis
  3. Continue: Most alerts are transient — don't overreact
  4. Kill (rare): Only if NaN persists after 10 checkpoints
