12.4 The NaN Story (S92–S94)

BiMDN training initially produced NaN losses within 100–500 episodes:

  1. Symptom: BiMDN losses → NaN
  2. Root cause 1: Scale mismatch — BiMDN outputs unbounded scale parameters
  3. Root cause 2: AMP interaction — fp16 underflow with small gradients
  4. Root cause 3: Single critic — Q-value overestimation → explosion
  5. Fix: Twin critics + gradient clipping + disable AMP for BiMDN + wheelbase correction
Insight: The NaN was not a simple bug — it revealed that BiMDN's scale outputs are fundamentally unstable with fp16. The fix is both numerical (twin critics, clipping) and architectural (correct wheelbase).

12.6 What We Learned

  1. The paper is reproducible but fragile. 5 critical bugs in our initial implementation, all subtle.
  2. Oscillatory dynamics are intrinsic. Not a bug in our code — the game is genuinely hard.
  3. BiMDN is sensitive. Requires warm-up, correct architecture, and careful numerics.
  4. Self-play CR = 0.55 is not a Nash. It's an oscillatory point, not a stable equilibrium.
