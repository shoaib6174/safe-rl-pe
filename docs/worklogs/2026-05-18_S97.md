#### EMA Update Logic
- **File:** `repro_gonultas_isler_2024/training/train.py:200-206`

- Pursuer trains against `ema_evader`, evader trains against `ema_pursuer`

### Critical Analysis & Fixes (Post-Implementation Review)

After thorough review, identified 10 issues across correctness, robustness, and research methodology. Implemented fixes in priority order.

#### Fix P0 #1: Backward Compatibility
- **Problem:** Default `ema_tau` was 0.005, so configs without the key silently enabled EMA
- **Fix:** Changed default to `0.0` in `training/train.py:82`
- **Impact:** Existing scripts using old configs now correctly run vanilla SP

#### Fix P0 #2: Config Consistency
- **Problem:** Only `config_belief_noamp.yaml` had `ema_tau`; other configs lacked it
- **Fix:** Added `ema_tau: 0.001` to `config.yaml`, `config_belief.yaml`, `config_vanilla.yaml`

#### Fix P0 #3: EMA Checkpoint Persistence
- **Problem:** EMA weights not saved; resuming training resets EMA state
- **Fix:** Save `ema_pursuer.pt` and `ema_evader.pt` in checkpoints and final checkpoint
- **Files:** `training/train.py:270-271, 284-287`
- **Verified:** EMA files appear in checkpoint directories

#### Fix P1: EMA Status Logging
- **Problem:** No way to tell from logs whether EMA is active
- **Fix:** Added `log_text()` to Logger, print EMA status at training start
- **Files:** `training/train.py:158-161`, `utils/logger.py:19-22`
- **Verified:** Smoke test shows `EMA=ON (tau=0.005)` in output

#### Fix P1: Tau Value Correction
- **Problem:** `tau=0.005` gives 63% convergence per episode (half-life = 0.69 episodes) — too fast for oscillations that cycle over thousands of episodes
- **Fix:** Changed default to `0.001` (half-life ≈ 3.5 episodes, 18% convergence per episode)
- **Mathematical analysis:** Documented half-life calculations for τ ∈ {0.0001, 0.0005, 0.001, 0.005, 0.01}

#### Fix P2: Unit Tests for EMA
- **File:** `tests/test_maddpg.py:56-115`
- `test_update_accepts_opponent_actor`: Verifies `update()` accepts external `nn.Module`
- `test_ema_update_slowly`: Verifies EMA moves by exactly τ·Δ per update and does not fully catch up
- **All tests pass**

#### Fix P2: EMA Evaluation Modes
- **File:** `evaluation/evaluate.py`
- Added `load_ema_policy()` helper for loading EMA weights
- Added 7 new evaluation matchups when EMA checkpoints exist:
  - `ema_pursuer_vs_evader`, `ema_pursuer_vs_random`, `ema_pursuer_vs_greedy`
  - `pursuer_vs_ema_evader`, `random_vs_ema_evader`, `greedy_vs_ema_evader`

#### Fix P2: Checkpoint Sweep Script
- **File:** `evaluate_checkpoint_sweep.py` (new)

- Computes oscillation amplitude: rolling std(CR_selfplay) over 20-checkpoint window
- Outputs CSV for analysis

## Decisions Made

| Decision | Rationale |
|----------|-----------|
| EMA update happens once per env step (after all n_updates) | More efficient; EMA changes slowly anyway |
| Vanilla fallback when `ema_tau <= 0` | Allows A/B comparison without code changes |
| EMA applied to actor only, not critic | Critic sees current opponent for accurate Q; actor trains against stable EMA |
| Default `ema_tau: 0.0` in code, `0.001` in configs | Backward compatibility: old configs without key run vanilla SP |
| Save EMA weights in checkpoints | Required for resume and for evaluating EMA policies |
| Lower default τ from 0.005 to 0.001 | Mathematical analysis: 0.005 half-life = 0.69 episodes (too fast); 0.001 = 3.5 episodes |
| EMA evaluation as conditional additions | Only computed when EMA checkpoints exist; no overhead for vanilla runs |
