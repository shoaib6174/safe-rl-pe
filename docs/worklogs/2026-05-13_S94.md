## Work Done

### Fix: Actor Update with Twin Critics

**Problem:** In S93's twin critic implementation, the actor loss computed the policy gradient using only `q1_actor`:
```python
actor_loss = -q1_actor.mean()  # OLD — exploits critic1 overestimation
```

Even though target Q used `min(target_q1, target_q2)`, the actor could still overfit to critic1's overestimation, creating a positive feedback loop → Q explosion → NaN.

**Fix:** Changed actor loss to use the conservative minimum:
```python
actor_loss = -torch.min(q1_actor, q2_actor).mean()  # NEW
```

Applied in both AMP and non-AMP paths (`agents/maddpg.py:177,189`).

### VectorizedEnvRunner Implementation

Created `training/vectorized_env.py` with `VectorizedEnvRunner` class:
- Manages N independent `PursuitEvasionEnv` instances
- Per-env frame stacking buffers (auto-padded on reset)
- Per-env `BeliefStateManager` instances (history cleared on reset)
- Frame skip handled internally (repeats action, accumulates rewards)
- Automatic env reset on episode completion
- Returns transitions for replay buffer + completed episode metrics + BiMDN info

Key design: continuous rollout — envs that finish reset immediately and continue contributing data.

### train.py Rewrite

Replaced episode-based outer loop with step-based continuous rollout:
```python
while completed_episodes < episodes:
    stacked_p, stacked_e = runner.get_stacked_obs()
    actions_p = [pursuer.select_action(o, noise_sigma) for o in stacked_p]
    actions_e = [evader.select_action(o, noise_sigma) for o in stacked_e]
    transitions, completed_eps, bimdn_info = runner.step(...)
    # store transitions, do MADDPG updates, update curriculum
```

Update frequency: `n_envs * update_freq` gradient steps per parallel step (8 updates with 8 envs), maintaining ~1 update per env step as in the original code.

Curriculum applied globally based on total completed episodes across all envs.

## Decisions Made

| Decision | Rationale |
|----------|-----------|
| **Actor uses min(q1, q2)** | Prevents actor from exploiting overestimation in either critic. Required for twin critics to actually work. |
| **8 updates per parallel step** | `n_envs * update_freq` maintains ~1 MADDPG update per env step, matching original training intensity. |
| **No multiprocessing** | Env is pure numpy/Python, very fast. SyncVectorEnv-style sequential batching is sufficient and simpler. |
| **Log every n_envs episodes** | With 8 envs, episodes complete in bursts. Logging every 8 episodes gives stable aggregates. |
