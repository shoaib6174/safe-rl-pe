### BiMDN Integration
- Created `training/belief_manager.py` — `BeliefStateManager` class
  - Rolling history buffer (200 obs, downsampled 10x → 20 at 1Hz)
  - Belief computation via BiMDN weighted mean
  - Training sample storage (25K buffer)
  - BiMDN training step (batch size 256, Adam LR=0.002)
- Updated `training/train.py` with `use_belief` config toggle (default **false**)
  - When false: vanilla MADDPG, obs_dim=22 (11×2 frames)
  - When true: MADDPG + BiMDN, obs_dim=26 (13×2 frames: 11 raw + 2 belief)
  - BiMDN stores training samples at each sim step, updates every 10 steps
  - Checkpoints include BiMDN weights when belief enabled

### Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| `use_belief: false` by default | Spec risk mitigation: verify vanilla MADDPG trains first, then add BiMDN complexity |
| Separate `BeliefStateManager` per agent | Each agent maintains its own history and belief about the opponent |
| History at sim rate (10Hz), downsample to 1Hz | Matches spec: 200 obs → 20 at 1Hz for BiMDN input |
| Belief appended per-frame before stacking | Each frame in stack gets its own belief (13-D → 26-D stacked) |
| BiMDN training samples stored every step | Maximizes data efficiency; updates every 10 steps for compute efficiency |

| Decision | Rationale |

| **Run vanilla MADDPG first, then add BiMDN** | Spec risk mitigation + historical evidence: our 5 failed approaches all had compounding issues. Isolating algorithmic variables is essential. |
| **Obs_dim = 22 (vanilla) or 26 (with belief)** | Frame stacking: 2 frames × (11 raw + optional 2 belief) |
| **BiMDN training buffer = 25K, update every 10 steps** | Matches paper hyperparameters exactly |
| **Commit checkpoints every 250 episodes** | Matches paper evaluation protocol |
